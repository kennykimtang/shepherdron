Shepherdron 웹 시연판

https://kennykimtang.github.io/shepherdron/

브라우저에서 군중 밀집도 인식과 드론 유도 판단을 그대로 돌립니다.
설치가 필요 없어 발표장 PC 에서 링크만 열면 됩니다.

| 파일 | 내용 |
|---|---|
| `vision.js` | KDE 밀집도 · ROI 면적 · 등급 · 전술 투영 · 유도 방향 · 임무 상태기계 |
| `detector.js` | 머리 검출 · 타일 분할 추론 (onnxruntime-web, WebGPU → WASM) |
| `link.js` | 폰 ↔ PC WebRTC 연결 · QR |
| `app.js` | 화면 그리기 · 조작 |
| `head.onnx` | 머리 검출 YOLO11n 가중치 (11 MB, AGPL-3.0) |

쓰는 방법 세 가지

| 모드 | 쓸 곳 |
|---|---|
| 폰 카메라 연결 | 발표장 PC 가 화면, 폰이 카메라. QR 을 찍으면 붙는다 |
| 이 기기 카메라 | 한 기기에서 전부 |
| 영상 파일 | 녹화본으로 같은 처리 |

`vision.js` 는 저장소의 `vision/density_field.py`, `vision/tactical.py`,
`flight/mission.py` 를 옮긴 것입니다. 브라우저 API 를 쓰지 않으므로 node 로
검증할 수 있습니다.

다만 지금은 웹판이 앞서 있습니다. 머리 검출(축척 0.23 m), 목표 좌표
시간 필터, 유도 방향 히스테리시스는 웹판에만 들어가 있고 파이썬판은
아직 전신 검출(1.7 m)과 필터 없는 최대점을 씁니다. 같은 영상에서 두
결과가 다르게 나오는 건 이 때문이며, 파이썬판 반영은 남은 일입니다.

검출은 머리를 봅니다. COCO 로 학습한 yolov8n 의 person 은 전신 박스를
기대하고 배운 탓에, 몸통이 앞사람에 가린 군중에서 거의 못 잡습니다.
마라톤 출발선 사진(2589x1458, 300명 이상)으로 재 보니 앞줄 4명이
전부였습니다. 군중에서 끝까지 보이는 건 머리뿐입니다.

머리 모델 네 가지를 같은 사진 같은 조건(conf 0.25, CPU)으로 재 보고
YOLO11n 머리 전용(huggingface.co/wesjos/YOLO-head-detection, AGPL-3.0)을
골랐습니다. 추론이 느리면 박스가 영상보다 늦게 따라와 눈에 띄게 어긋나므로,
군중 검출에서는 조금 덜 잡더라도 빠른 쪽이 낫습니다.

| 모델 | 크기 | 머리 | 지연 (CPU) |
|---|---|---|---|
| CrowdHuman 11s 2클래스 | 38 MB | 136 | 303 ms |
| **11n-head** | **11 MB** | **120** | **94 ms** |
| v8n-head | 12 MB | 118 | 110 ms |
| 11s-head | 38 MB | 101 | 253 ms |

검출에 넘긴 프레임을 따로 떠 두고 그 위에 결과를 그립니다. 살아 있는 영상
위에 그리면 박스가 한두 프레임 전 머리 자리에 찍힙니다. 버퍼는 둘입니다.
하나는 지금 추론에 들어가 있는 프레임, 다른 하나는 화면에 떠 있는 결과와
짝이 맞는 프레임입니다. 하나로 돌리면 다음 추론이 시작되는 순간 그림만
새 프레임으로 바뀌어 추론이 도는 내내 다시 어긋납니다. 툴바의 프레임
맞춤(`s`)으로 끌 수 있습니다.

멀리 있는 사람까지 봐야 할 때는 화면을 NxN 으로 쪼개 조각마다 추론을
돌립니다(툴바 분할, 단축키 `t`). 조각이 맡는 넓이가 1/N² 이라 같은 사람이
N 배 크게 들어갑니다. 머리 모델에서는 분할 없이도 충분해 기본은 꺼 둡니다.

축척(m/px)은 머리 세로를 0.23 m 로 두고 역산합니다. 촬영 구역의 실제 넓이를
툴바에 넣으면 그 값으로 바로 환산하므로 더 정확합니다.

운용 절차는 [DEMO.md](../DEMO.md) 를 보세요.
